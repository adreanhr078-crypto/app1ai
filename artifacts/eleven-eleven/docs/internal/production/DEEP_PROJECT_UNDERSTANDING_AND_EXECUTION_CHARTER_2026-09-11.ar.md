# 11:11 — Echo Network
## وثيقة الفهم العميق وميثاق التنفيذ

**الإصدار:** 1.0  
**التاريخ:** 2026-09-11  
**الغرض:** إعطاء أي مدير أو وكيل أو شات جديد صورة واحدة دقيقة عن اللعبة، ترتيب إنتاجها، حالتها المثبتة، وحدود القرار.  
**طبيعة الوثيقة:** مرجع تنفيذ داخلي مشتق من الـCanon والـBlueprint. لا تضيف أحداثاً إلى القصة ولا تمنح أي مرحلة اعتماداً جديداً.

## 1. ما الذي نبنيه فعلاً؟

11:11 — Echo Network لعبة قصصية سينمائية من منظور الشخص الثالث، تستخدم المانهوا كذاكرة حية داخل نظام رقمي، ثم تحوّل اللاعب تدريجياً من قارئ ومحلل إلى شخص عالق داخل التجربة نفسها. جوهر اللعبة ليس حجم الخريطة؛ جوهرها أن يشعر اللاعب بأن النظام يفهم خوف Echo قبل أن يفهمه هو.

تعمل اللعبة عبر اتصال واحد بين أربعة أشياء:

1. **المانهوا:** مصدر المشهد والرمز والذكرى والـCanon للجزء الأول.
2. **النظام الحي:** Mission Control، الألغاز العادلة، الإيصالات، والانتقالات التي تجعل الواجهة جزءاً من القصة.
3. **العالم ثلاثي الأبعاد:** استكشاف، فحص، تفاعل، تخفٍّ، هروب، ثم قتال عندما يصبح القتال مبرراً سردياً وميكانيكياً.
4. **العلاقة النفسية:** Echo وYuki وShizuka وKinja وZ-000 لا يُستخدمون كأسماء لتحريك الحبكة؛ لكل شخصية خوف ورغبة وسر ونقطة انهيار وتحوّل قابل للعب أو المشاهدة.

القيمة المستهدفة هي تعلق اللاعب، فضوله، خوفه، وإحساسه بالتمكن. أي نظام لا يزيد واحداً من هذه القيم أو لا يثبت اعتماداً لاحقاً يبقى خارج الشريحة.

## 3. فهم التجربة النفسية

المسار العاطفي المقصود لـEcho هو:

`إنسان ضعيف → ضحية → باحث عن تفسير → شخص ينهار → متعاقد مع قوة مجهولة → كائن يخاف منه العالم`.

لا نعرض هذه العبارات كشرح مباشر. نثبتها بالفعل والإيقاع:

- **الضعف:** حركة ذات وزن، مجال رؤية خانق، تفاعل بطيء قليلاً، وأبواب لا تستجيب إلا بعد فهم المكان.
- **الضحية:** آثار بشرية وبيئية تسبق ظهور التهديد؛ يرى اللاعب النتيجة قبل أن يعرف الفاعل.
- **البحث:** مسح، انعكاسات، أجزاء مانهوا، وأدلة متعارضة تعطي إجابة صغيرة وتفتح سؤالاً أكبر.
- **الانهيار:** تغيرات صوتية وبصرية محسوبة، مع خيار Reduced Motion وعدم معاقبة اللاعب بحذف تقدم أو تلميح.
- **العقد:** قرار لاحق له ثمن واضح؛ لا يُفتح في G0 ولا يُلمّح إليه كقدرة مبكرة لمجرد رفع الحماس.
- **الخوف من الكائن:** نفس هوية Echo الجسدية والنفسية تصبح مرآة لـZero؛ العلامة `EX-011` تبقى مباشرة على الجلد، ويضاف أثر التحول حولها.

قاعدة الاحتفاظ الصحية: كل جلسة تترك سؤالاً واضحاً، وكل عودة تعطي كشفاً أو إتقاناً أو علاقة ذات معنى. لا نستخدم ضغطاً زائفاً أو فقدان streak أو إشعارات قسرية.

## 4. ما هو Canon وما هو اقتراح؟

الجزء الأول المعتمد هو المصدر الدقيق. لا نثبت خلفية جديدة للأب، أو نهاية إضافية، أو عدو جديد، أو قدرة، أو دافع، اعتماداً على صورة AI أو ورقة وكيل. أي مادة لاحقة للجزء الأول تحمل وسم **Provisional** حتى يدخل إصدار Canon جديد بموافقة المالك.

القرارات المحمية حالياً:

- Echo هو البطل.
- Yuki صديقة الطفولة ذات الشعر الأبيض.
- علامة Echo هي `EX-011` مباشرة على جلد الرقبة.
- Zero هو امتداد فاسد لـEcho؛ لا يستبدل الوجه أو الجسد أو العلامة.
- القتال أو قتل إنسان قبل التحول ممكنان إذا خدمهما المشهد، لكن بلا قدرات Zero. هذا قرار نطاقي لاحق، وليس سبباً لفتح combat في G0.
- الخروج من العالم الحضري بعد المانهوا فكرة مستقبلية provisional؛ لا تُنتج الآن.

## 5. الحالة التقنية المؤكدة

المسار المستهدف للـ3D هو Godot `4.7.2` ضمن نطاق مقاس. Blender `5.2.1 LTS` هو مسار إعداد الأصول. VRoid Studio `2.14.0` يوفّر نقطة البداية للشخصية. ComfyUI وعُقده موجودة، لكن أوزان الإنتاج والـworkflow القابل للتكرار يحتاجان بوابة منفصلة.

الحدود المعمارية غير القابلة للتفاوض:

- Godot يعرض الحركة والتفاعل والمشهد، لكنه لا يملك سلطة الحساب، المكافآت، الحفظ، المخزون، صحة اللغز، أو تقدم القصة.
- أي Session bridge في الشريحة TEST_ONLY، idempotent، ولا ينشئ receipt.
- التصادم منفصل عن المجسم المرئي؛ لا نستخدم شكل الشخصية كـcollision ضمنياً.
- اللاعب يرسل command، والجهة السلطوية تعيد state؛ لا نكتب الحقيقة من واجهة العرض.
- الجودة تتدرج حسب الجهاز عبر Low/Medium/High/Ultra، لكن الحقيقة السردية والوصولية لا تتغير.

مسار الأصل المعتمد:

`مانهوا/Reference → مواصفة شخصية → VRoid base → Blender identity/refinement → rig/weights/animations → GLB validated → Godot import → runtime capture`.

VRoid الخام ليس Echo النهائي، وصورة AI ليست نموذجاً ثلاثي الأبعاد، وGLB ينجح تقنياً فقط إذا نجح أيضاً بصرياً ونفسياً داخل اللقطة.

## 6. الوضع الحالي بدقة

### مثبت

- مشروع Godot تجريبي مستقل في `art/godot/technical-proofs/sector-11-foundation/`.
- حركة مرتبطة بالكاميرا، كاميرا منظور ثالث، تفاعل أساسي، HUD اختبار، وقياس frame time.
- غرفة Sector 11 صغيرة مولدة إجرائياً مع إضاءة ونقاط تفاعل وفصل visual/collision geometry.
- عقود launch context وplayer command وauthoritative state.
- أوامر import/test/smoke/run في `tools/godot/run-godot.ts` وسكربتات npm المقابلة.
- ملف VRoid محفوظ في `art/production/echo-vroid-foundation/source/Echo_Foundation_v0.vroid`.
- اختبارات headless وGLB الهيكلية السابقة نجحت ضمن حدودها.
- تقرير تدقيق Antigravity محفوظ، ويصنف أوراقه وصوره كمرشحات أو مراجع غير ملزمة.

### غير مثبت أو مرفوض

- لا يوجد VRM مُصدّر ومثبت بالبصمة.
- لا يوجد Echo بصري مقبول أو مطابق للـCanon داخل Godot.
- `echo_foundation_v1.glb` placeholder تقني مرفوض كهوية نهائية.
- اللقطة المرئية السابقة أظهرت تموضعاً/مقياساً سيئاً للكاميرا؛ جودة التشغيل البصرية **FAIL** إلى أن تعاد المعاينة.
- لا توجد نسبة AAA صالحة؛ عدد المثلثات أو نجاح parse لا يساوي جودة AAA.
- ComfyUI لا يملك بعد smoke workflow موثقاً مع seed وhash وprovenance؛ سكربت Antigravity السابق لم يرسل فعلياً طلبات توليد مكتملة.
- Computer Use الأصلي كان غير متاحاً في آخر جلسة؛ يجب إعادة اكتشاف نافذة التطبيق قبل أي تحكم.

## 7. المرحلة التنفيذية الحالية: G0

الهدف ليس إنتاج كمية من الأصول. الهدف إثبات أن نواة اللعبة قابلة للعب ومقنعة قبل توسيعها.

| البوابة | المطلوب | دليل القبول |
|---|---|---|
| G0.1 | مشروع Godot معزول وقابل للاستيراد | import/headless smoke وسجل مسار واضح |
| G0.2 | Echo base من VRoid مروراً بـBlender | VRM/Blend/GLB وبصمات ومصدر وشروط استخدام |
| G0.3 | Rig وidle/walk/interaction | animation playback ومواضع مفاصل سليمة |
| G0.4 | كاميرا وحركة | مسافة مريحة، اتجاه صحيح، لا clipping أو ملء غير مقصود للشاشة |
| G0.5 | تفاعل واحد مفهوم | prompt، input، استجابة، وحالة خطأ قابلة للاستعادة |
| G0.6 | غرفة Sector 11 | إضاءة مقصودة، silhouette مقروء، visual/collision parity |
| G0.7 | الوصول والأداء | Reduced Motion، mute/volume، نص مقروء، frame evidence على جهاز المرجع |
| G0.8 | بوابة القرار | checklist مكتمل، self-critique، إصلاحات آمنة، إعادة تحقق، ثم Owner review |

لا تنتقل الشريحة إلى G1/G2 التالي لمجرد أن الملف يفتح. يجب أن يمر Echo نفسه والكاميرا والغرفة كلّها في لقطة تشغيل يمكن مراجعتها.

## 8. خطة العمل التالية

1. استعادة Computer Use الرسمي أو استخدام مسار Blender المحلي إذا كان ملف VRoid يمكن تحويله بأداة مثبتة، مع حفظ الأصل قبل أي تغيير.
2. تصدير VRM من VRoid، تسجيل الإصدار واسم الـsample وشروطه، وحفظ hash.
3. فحص إضافة VRM المحلية في بيئة Blender قبل تنزيل أي إضافة جديدة.
4. تنقيح الشخصية في Blender: silhouette، الشعر الذي يغطي الجهة اليسرى من الوجه، ملابس مدنية بسيطة، EX-011 على الجلد، أوزان سليمة، ومواد قابلة للعرض في Godot.
5. تصدير GLB، إعادة استيراده، تشغيل validator، ثم تسجيل tri/material/bone/animation/texture budgets.
6. استبدال placeholder في Godot، وضبط scale وpivot وcamera distance وlook-at وfloor contact.
7. تشغيل اختبار الحركة والتفاعل داخل الغرفة، والتقاط runtime evidence على دقة العرض المستهدفة.
8. كتابة نتيجة G0: `PASS` أو `FAIL` أو `UNVERIFIED` لكل بند، وعدم رفع نسبة الجودة إذا بقيت المعاينة البصرية غير مؤكدة.

## 9. معيار الجودة الفني والنفسي

نراجع الأصل والمشهد من خمس زوايا متزامنة:

| البعد | سؤال المراجعة |
|---|---|
| الهوية | هل يمكن تمييز Echo من silhouette وفي اللقطة القريبة؟ |
| الإنسانية | هل يبدو شخصاً عاش حياة عادية، لا بطل gacha؟ |

| اللعب | هل وزن الحركة والتفاعل يعطي اللاعب سيطرة مفهومة؟ |
| السينما | هل الإضاءة والكاميرا تدعمان الشعور ولا تخفي العيوب؟ |

إذا فشل البعد البصري أو النفسي، تبقى النتيجة **UNVERIFIED/FAIL** حتى لو نجح GLB validator أو Godot parser.

## 10. بروتوكول الوكلاء

- **المالك/Creative Director:** يعتمد Canon، الهوية، قبول التجربة، والانتقال بين البوابات.
- **Sol:** architecture، Godot، العقود، الأداء، والهجرة مع evidence.
- **Blender/VRoid:** إنتاج الأصول وتنقيحها وفق reference؛ لا يقرر القصة.
- **ComfyUI:** استكشاف مرئيات أو سد فجوة محددة بعد provenance؛ لا يقفل وجه Echo تلقائياً.
- **Antigravity:** مهام بسيطة قابلة للتحقق فقط، مثل تلخيص ملف أو فحص اسم/مسار أو اقتراح قائمة؛ لا commit أو push أو تنزيل أوزان أو إعلان اعتماد دون مراجعة.

كل تكليف يجب أن يحدد المدخل، المخرج، مكان الحفظ، قيد Canon، ميزانية الأداء، واختبار القبول.

## 11. مخاطر القرار الحالية

- **أعلى خطر:** قبول نموذج جميل لكنه لا يشبه Echo ولا يحمل EX-011؛ العلاج هو فصل visual approval عن structural validation.
- **خطر النطاق:** القفز إلى العالم المفتوح أو Zero أو القتال قبل إثبات الحركة؛ العلاج هو تجميد G0 بهذه الوثيقة.
- **خطر الأدوات:** تكرار ادعاء أن ComfyUI أو VRoid اكتمل لأن عملية بدأت؛ العلاج هو hashes، logs، runtime evidence، ونتيجة بوابة صريحة.
- **خطر المعمارية:** إعادة بناء الحقيقة في Godot أو إنشاء محرك ثانٍ؛ العلاج هو إبقاء authority boundaries والعقود الحالية.
- **خطر الاستمرارية:** خلط أوراق Antigravity غير الـCanon مع المانهوا؛ العلاج هو هرم السلطة ووسم كل اقتراح بـProvisional.
